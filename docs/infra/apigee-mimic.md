# Apigee-style gateway flow (GCP mimic) [VERIFIED]

Mimics the real GCP JWT flow end to end in the test rig:

```
client ──(user JWT from IdP)──> nginx gateway ──(service JWT + mTLS)──> pgrmapper ──> postgrest
         │                          ▲
         └── keycloak-mockup (IdP) ─┘  (verifies user JWT with the IdP public key)
```

| GCP concept | Rig component |
|---|---|
| Identity Platform / Firebase Auth (IdP) | `idp` container: calcite/keycloak-mockup (OIDC mock, JWKS endpoint) |
| Client acquires ID token from IdP | host script `scripts/idp-token.sh` (auth-code flow driven with curl, against `localhost:5151`) |
| Apigee VerifyJWT policy | nginx njs handler verifying the user JWT (RS256 vs IdP public key, exp/iss/aud) |
| Apigee GenerateJWT policy | same njs handler signing a **service JWT** (RS256, gateway private key) embedding the original user JWT |
| Southbound service auth (Apigee → backend) | pgrmapper verifies the outer service JWT (gateway public key) **and** the embedded user JWT (against the IdP **JWKS** endpoint), plus mTLS |
| Backend enforcement | pgrmapper uses `X-User-Role` (set by nginx from the verified user JWT) for the access_filter projections; PostgREST verifies the service JWT itself via a JWK set |

## Verified behaviors

- alice (`editor`) → 4 columns; bob (`manager`) → all 6; carol (`viewer`) →
  `id,title` only — projections follow the access_filter rules per role.
- `select=*` and explicit selects are intersected with the visible columns;
  `select=done` as viewer → `403`.
- No token → `401 missing user JWT`; garbage token → `401 invalid user JWT`
  (nginx VerifyJWT).
- pgrmapper rejects a service JWT without a valid embedded user JWT.
- Legacy mode (driver debugging): HS256 `pgjwt` tokens still work against
  PostgREST directly and through a manually-run pgrmapper (port 8000) —
  PostgREST accepts both token families via a JWK set.
- mTLS between gateway and pgrmapper unchanged (no client cert → reset).

## Why njs and not auth_jwt

The official nginx images (both `nginx:1.27` and `nginx:1.27-alpine`) are
built **without** `ngx_http_auth_jwt_module` (verified: `unknown directive
"auth_jwt"`). The `njs` module *is* shipped (`ngx_http_js_module.so`), and its
WebCrypto API verifies and signs RSA JWTs. One `js_content` script
(`nginx/conf.d/apigee.js`) covers VerifyJWT, claim extraction and
GenerateJWT.

## njs implementation notes (all hit and fixed during verification)

- `load_module` must be in the main `nginx.conf` (mounted at
  `/etc/nginx/nginx.conf`), not in a `conf.d` file.
- `crypto.subtle` lives on the njs **global** `crypto` object; importing the
  node-style `'crypto'` module shadows it (leaving only
  `createHash`/`createHmac`).
- `crypto.subtle.importKey` requires **DER bytes** (`Uint8Array`), not PEM
  text — PEM headers must be stripped and the body base64-decoded.
- Base64 padding must be handled correctly in hand-rolled decoders (a
  256-byte signature must decode to 256 bytes, not 258).
- `fs.readFileSync(path)` returns a byte string; pass `'utf8'` for JS string
  methods.

## Keys and certificates (all generated by `scripts/gen-certs.sh`)

| File in `certs/` | Used by | Purpose |
|---|---|---|
| `idp-private.pem` | idp container (inlined into generated `idp-config.yaml`) | signs user JWTs |
| `idp-public.pem` | nginx (njs) | verifies user JWTs |
| `gateway-jwt.key` (PKCS8) | nginx (njs) | signs the service JWT |
| `gateway-jwt-public.pem` | pgrmapper | verifies the service JWT |
| `jwt-secrets.json` | postgrest (`PGRST_JWT_SECRET=@/certs/jwt-secrets.json`) | JWK set: RS256 gateway key + legacy HS256 secret |
| existing `ca/`, `server.*`, `client.*` | gateway ↔ pgrmapper | mTLS (unchanged) |

## Components

### idp (keycloak-mockup)

- Image `ghcr.io/calcite/keycloak-mockup:latest` (Python app; amd64-only, runs
  under qemu emulation — fine for a non-Go binary). `platform: linux/amd64`
  is set in compose.
- Published on `IDP_PORT` (5151) so host clients reach it directly, like a
  real external IdP.
- Config: tracked `idp/config.example.yaml` (users alice/editor, bob/manager,
  carol/viewer; realm `myrealm`, client `myclient`); `gen-certs.sh` renders
  `certs/idp-config.yaml` with the IdP private key inlined.
- The mockup does **not** support the password grant; `scripts/idp-token.sh`
  drives the authorization-code flow entirely with curl (form login →
  `?code=` redirect → token exchange).
- Realm, client_id and issuer are driven by `.env` (`IDP_REALM`,
  `IDP_CLIENT_ID`, `IDP_PORT`): `gen-certs.sh` renders them into
  `certs/idp-config.yaml` (IdP) and `certs/apigee-config.json` (issuer/aud
  expected by the njs handler); pgrmapper gets them via compose env.
  Changing them requires cert regeneration
  (`rm certs/ca.crt && ./scripts/provision.sh`).

### gateway (nginx + njs)

- `nginx/nginx.conf`: official config + `load_module ngx_http_js_module`.
- `nginx/conf.d/gateway.conf`: `js_import apigee`, `js_var $service_jwt`,
  `js_var $user_role`; `location /` uses `auth_request /_apigee_auth` (the
  internal njs subrequest verifies the user JWT, signs the service JWT and
  sets the two variables, which auth_request propagates to the main
  request), then a direct `proxy_pass https://pgrmapper:8443/` with mTLS
  sets `Authorization: Bearer $service_jwt` and `X-User-Role: $user_role`
  and **streams the response** (no buffering, so arbitrarily large result
  sets work — the earlier `js_content` subrequest relay hit
  `subrequest_output_buffer_size` limits and broke on big tables).
- `nginx/conf.d/apigee.js`: verify → claims → sign → set variables.

### pgrmapper

- New env: `PGMAPPER_GATEWAY_JWT_PUBLIC_KEY` (service JWT, RS256),
  `PGMAPPER_IDP_JWKS_URL` (`http://idp:5151/.../certs`, fetched with httpx,
  keys built with `jose.jwk.construct`), `PGMAPPER_IDP_AUDIENCE`
  (default `myclient` — python-jose requires the audience when `aud` is
  present).
- Gateway mode (header `X-User-Role` present): verify service JWT → verify
  embedded user JWT against the IdP JWKS → role from the header. Any failure
  → `401`.
- Legacy mode (no header): unchanged HS256 `PGRST_JWT_SECRET` flow.

### postgrest

- `PGRST_JWT_SECRET` now points at the generated JWK set
  (`@/certs/jwt-secrets.json`) so it verifies both the RS256 service JWTs
  (gateway) and the legacy HS256 tokens (driver tools).

## Host usage

```sh
ALICE=$(scripts/idp-token.sh alice alice123)          # user JWT from the IdP
curl -H "Authorization: Bearer $ALICE" http://localhost:$NGINX_PORT/todos
curl -H "Authorization: Bearer $ALICE" "http://localhost:$NGINX_PORT/todos?select=*"
```
